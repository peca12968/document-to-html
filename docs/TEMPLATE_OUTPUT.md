# 靜態 HTML 範本輸出規格

## 目標與目前狀態

使用者於 2026-10-29 提供聲明書 HTML / Razor 範例，確認目標為：先產生可直接放入專案、讓工程師看懂並維護的靜態 HTML 範本，後續再由 AI 加入各種輸入框、資料綁定及驗證。

1.3.0 已加入「結構化 HTML＋CSS」靜態範本模式：正常文件流、區段、表格、欄位留白及 Base64 PNG 圖形。使用者選定的高還原圖片版仍保留。以下為輸出標準；自動辨識仍可能產生錯字、錯誤欄位配對、漏掉黑白掃描圖形或錯誤表格合併，產物需人工核對，不代表任意文件已能一鍵正確重建。

## 第一階段交付

- 預設產生獨立 HTML，可離線預覽；不依賴框架、後端、CDN 或執行 OCR 才能顯示。
- 依文件內容整理標題、正文、商品表格、審閱方式、簽署區、日期及頁尾等區塊。實際區塊依來源文件決定，不套用特定銀行文件的固定內容。
- 使用 `h1`、`p`、`section`、`table`、`thead`、`tbody` 等易懂結構；類別名稱表達用途，例如 `product-table`、`signature-section`。
- CSS 集中、共用，有一致縮排及必要的區塊註解；線條以 `border` 畫出。
- 文字以完整段落保存，表格使用真實列、欄及必要的合併儲存格；主要內容採正常文件流，增減文字能自然排版。
- 空白欄位先用底線、空白儲存格或有名稱的佔位元素呈現。先保留表單骨架，不提前推定資料庫欄位、API 或驗證規則。
- 圖片用於 Logo、照片、印章等圖形，允許 `<img src="data:image/png;base64,...">`；整頁圖片或大量逐字座標元素不算完成範本輸出。目前自動保留符合大小限制的原生 PDF 圖片、彩色圖形及其鄰近文字，掃描黑白圖形可能需人工補入。
- 勾選框及勾記同樣使用原稿小圖片，以 `.choice[data-choice]` 容器包住 `.choice-image`；後續再由專案加入透明 checkbox 或隱藏的勾選控制層。初始不輸出 `input` 或 `checked` 資料、不自行清除原稿勾記。幾何與 OCR 只能找出候選符號，未定位的符號可能保留為文字，並非已確定的業務欄位或勾選狀態。
- 依文件需要設定紙張、頁邊距及列印樣式。頁尾可在適當情況使用定位，但必須檢查與正文是否重疊。

## 後續交給 AI 的工作

可針對具名區塊提出修改，例如「委託人姓名改成輸入框」、「商品表格可新增列」、「審閱方式改為單選」、「接入專案既有 ViewModel」。這些修改應能在對應區塊完成，不需要重新辨識 PDF 或重寫整頁排版。

勾選區塊範例（省略圖片資料）：

```html
<span class="choice" data-choice="page-1-choice-1">
    <img class="choice-image" src="data:image/png;base64,..." alt="原稿勾選框或記號">
</span>
```

`data-choice` 只在同一次輸出的頁面內識別圖形，重新轉換後可能改變；接入業務系統時應改成有意義的欄位名稱。後續添加控制項時，應同時提供可存取的標籤、鍵盤操作與焦點提示。

## HTML 與 Razor

一般 HTML 的 CSS 使用 `@page`、`@media`，不包含 `@{ Layout = null; }`。若指定輸出 Razor View，才依目標專案加入 Razor 設定，並將樣式中的 `@` 正確跳脫。範本不自行加入不明來源的 Razor 表達式。

## 驗收

1. 工程師能直接從原始碼找到標題、表格、簽名及空白欄位。
2. 修改一段文字或增加一列商品，不必重新計算整頁座標。
3. 範本可單獨預覽，能帶入專案再加入互動功能。
4. 使用原稿核對文字、表格關係、勾選狀態及分頁；辨識不確定處必須可追查，不能宣稱已自動推知完整業務意義。
5. 使用者提供的範例是可讀性標準；具體 CSS 可整理改善，例如重複宣告、欄寬總和及列印溢出。
